# RequestForwarder (IRequestForwarder)

Proxies authenticated requests to llama-server backends with header injection, error handling, and response forwarding. Core component for OpenAI-compatible API routing.

## Dependencies

| Dependency | Purpose |
|------------|---------|
| `IHttpClientFactory` | HTTP client for backend requests |
| `HeaderValueInjector` | Maps HTTP headers to JSON body fields |
| `ILogger<RequestForwarder>` | Request/response logging |

## Core Responsibilities

- Forward `/v1/*` proxy requests to llama-server backends
- Inject HTTP headers into request body (if enabled in config)
- Handle backend errors and timeouts
- Preserve hop-by-hop headers for debugging

## Proxy Flow

```
Client request received (/v1/chat/completions)
  → RequestLoggingMiddleware logs request details
  → BasicAuthMiddleware validates credentials
  → RequestForwarder.ForwardAsync() called
    → Create HttpRequestMessage with backend URL
    → Inject headers into body (HeaderValueInjector.Inject())
    → Copy hop-by-hop headers to outgoing request
    → Send via HttpClient
  → ResponseUsageMiddleware captures response body
  → Return proxied response to client
```

## Header Injection

**Enabled via:** `RouterConfig.EnableBodyHeaderInjection` (default: true)

**Mapping config:** `RouterConfig.BodyHeaderMappings`

Example mapping:
```json
{
  "x-client-id": "clientId",
  "x-debug": "debug",
  "x-priority": "priority"
}
```

**Behavior:** HTTP headers mapped to JSON body root-level fields with auto-type conversion (bool/int/double/string).

See [[entities/HeaderValueInjector]] for injection details.

## Backend URL Resolution

**Priority order:**
1. Per-model `BackendUrl` from `ModelConfig` (if specified)
2. Global `BackendUrl` from `RouterConfig` (default: `http://localhost:8001`)

**All models use port 8001** — sequential execution enforced by [[entities/ModelManager]].

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Backend timeout | Return 504 Gateway Timeout with error message |
| Backend unreachable | Return 502 Bad Gateway |
| llama-server error (4xx/5xx) | Forward status code and body unchanged |
| Invalid JSON response | Log warning, return 502 with error details |

## Hop-by-Hop Headers

**Skipped headers:** `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Transfer-Encoding`, `Upgrade`

**Preserved headers:** All others (including `X-Llama-*` custom headers)

**Purpose:** Prevent proxy loop issues while maintaining debugging headers.

## Testing Patterns

**RequestForwarderTests.cs:**
```csharp
[Fact]
public async Task ForwardAsync_WhenBackendReturnsSuccess_ReturnsSameStatusCode()
{
    // Arrange
    var handler = new MockHttpMessageHandler(HttpStatusCode.OK, "{\"choices\":[{\"finish_reason\":\"stop\"}]}");
    var clientFactory = new HttpClientFactory(handler);
    
    var forwarder = new RequestForwarder(clientFactory, null, logger);
    
    // Act
    var response = await forwarder.ForwardAsync(context, "http://localhost:8001");
    
    // Assert
    Assert.Equal(HttpStatusCode.OK, response.StatusCode);
}

[Fact]
public async Task ForwardAsync_WhenBackendTimesOut_Returns504()
{
    // Arrange
    var handler = new MockHttpMessageHandler(TimeSpan.FromMilliseconds(1)); // Timeout
    var clientFactory = new HttpClientFactory(handler);
    
    var forwarder = new RequestForwarder(clientFactory, null, logger);
    
    // Act
    var response = await forwarder.ForwardAsync(context, "http://localhost:8001");
    
    // Assert
    Assert.Equal(HttpStatusCode.GatewayTimeout, response.StatusCode);
}
```

## Performance Notes

- **HttpClient pooling:** `IHttpClientFactory` manages connection reuse
- **Async streaming:** Response forwarded without full buffering (when possible)
- **Header injection:** Full body read into memory before forwarding (not suitable for large payloads)

## Critical Notes

- **Single backend port:** All models share port 8001 — model selection via `X-Llama-Model` header
- **Body modification:** Header injection modifies request body before forwarding
- **No retry logic:** Failures returned immediately to client
- **Timeout config:** Controlled by `RouterConfig.Timeouts` (see [[entities/ConfigRecords]])
