# LlaModem Architecture Documentation

## Summary

Created comprehensive architecture documentation for the llamodem repository using the annotate-guidance skill, then processed and structured wiki sources with entity pages, concept pages, and cross-references.

## Key Learnings

### Architecture Pattern
LlaModem uses a **layered architecture with dependency injection** rather than strict Clean Architecture:
- Single project structure (`LlaModem` net10.0-windows)
- Service-layer organization with interfaces + concrete implementations in `Services/`
- Configuration records as immutable POCO records in `Config/`
- Minimal API pattern for endpoint registration (extension methods like `MapStatsEndpoints()`)

### Core Components Documented
Created 12 entity pages covering:
- **Services**: DashboardService, UsageService, RequestForwarder, ModelManager, StatsService
- **Middleware**: ResponseUsageMiddleware, RequestLoggingMiddleware, BasicAuthMiddleware
- **Utilities**: DefaultModelLauncher (PowerShell process management), HeaderValueInjector, UsageExtractor
- **Configuration**: ConfigRecords (AppConfig, RouterConfig, ModelConfig, UsageConfig)

### Key Patterns Identified
1. **ModelLifecycleManagement** - Automatic lazy start, hot switching, idle shutdown (600s default), health checks
2. **UsageTrackingPattern** - SQLite persistence via Dapper with cost comparison against cloud models
3. **HeaderInjectionPattern** - HTTP headers mapped to JSON body fields with auto-type conversion (bool/int/double/string)
4. **MinimalAPIArchitecture** - Extension methods for endpoint registration, no controller boilerplate

### Data Flow
Request processing pipeline:
1. ResponseUsageMiddleware captures response body (non-streaming only)
2. RequestLoggingMiddleware logs request details (debug level)
3. BasicAuthMiddleware validates credentials on `/v1/*` routes
4. Endpoint handlers route to proxy or admin endpoints

Model lifecycle flow:
1. Client requests model via X-Llama-Model header
2. ModelManager.EnsureModelAsync() orchestrates start/switch
3. DefaultModelLauncher.StartAsync() launches PowerShell script
4. HealthChecker.PollAsync() waits for /health endpoint
5. RequestForwarder.ForwardAsync() proxies to backend

### Testing Strategy
- xUnit test project (LlaModem.Tests)
- In-memory mocks: InMemoryModelRepository, fake HTTP clients
- Focus on service logic and middleware behavior
- Endpoint routing not tested directly (integration tests in Minimal API pattern)
