# LlaModem Architecture Guidance — Summary

## Summary

This directory contains comprehensive architecture documentation for the llamodem repository, designed to help AI assistants understand and work with the codebase effectively. The documentation follows a layered structure with configuration records in `Config/`, core business logic in `Services/`, middleware components in `Middleware/`, and testing patterns in `LlaModem.Tests/`.

The project uses a minimal API pattern with dependency injection, interface-first service design, and immutable POCO configuration records. Key workflows include model lifecycle management (lazy start, hot switching, idle shutdown), usage tracking via SQLite persistence, and HTTP header-to-body injection for flexible client configurations.

## Key Takeaways

- **Layered architecture with DI**: Configuration records bound via `IOptions<T>`, services registered as singletons, middleware pipeline configured in `Program.cs`
- **Interface-first service design**: All services implement interfaces (`I*`) for testability and modularity
- **Minimal API pattern**: Endpoints defined via extension methods (`MapStatsEndpoints()`) rather than controllers
- **Usage tracking**: Non-streaming responses captured to SQLite with cost comparison against cloud models
- **Model lifecycle**: Automatic lazy start, hot switching, idle shutdown (600s default), and health checks
